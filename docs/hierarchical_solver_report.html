2. Mathematical Setup

2.1 Global System

The original circuit equation (e.g., for DC or one time-step of transient):

\[ \mathbf{M} \mathbf{v} = \mathbf{b} \]

Where:

  • \(\mathbf{M}\) = system matrix (e.g., \(G + C/h\) for transient)
  • \(\mathbf{v}\) = unknown node voltages
  • \(\mathbf{b}\) = RHS (current sources, history terms)

2.2 Partition-Level Notation

For partition \((i,j)\) (intm \(i\), part \(j\)), define:

  • \(\mathbf{v}_{i,j}^{(\text{int})}\) = internal node voltages
  • \(\mathbf{v}_{i,j}^{(\text{port})}\) = port/boundary node voltages

The local system for partition \((i,j)\):

\[ \begin{bmatrix} \mathbf{A}_{i,j} & \mathbf{B}_{i,j} \\ \mathbf{B}_{i,j}^T & \mathbf{D}_{i,j} \end{bmatrix} \begin{bmatrix} \mathbf{v}_{i,j}^{(\text{int})} \\ \mathbf{v}_{i,j}^{(\text{port})} \end{bmatrix} = \begin{bmatrix} \mathbf{b}_{i,j}^{(\text{int})} \\ \mathbf{b}_{i,j}^{(\text{port})} \end{bmatrix} \]
Matrix Definitions:
  • \(\mathbf{A}_{i,j}\) = mtx in mtxPart (internal-internal, sparse)
  • \(\mathbf{B}_{i,j}\) = cmtx in mtxPart (internal-port coupling, sparse)
  • \(\mathbf{D}_{i,j}\) = intm or schur in mtxPart (port-port, before Schur reduction)

Sparse vs dense port block: mtxPart::init_part_mtx1 (mtxPart.cc:180-192) allocates exactly one of the two. When Opts::EXACT_PART_MTX is true (the default, main.cc:219) and the level is bottom_level — i.e. at the partition level — it allocates the dense schur (dsMatrix); otherwise — notably at the intm level — it allocates the sparse intm (spMatrix). This distinction matters for sparsification: see Section 15.

Phase 1: Partition Schur Complement

3. Partition Schur Complement

3.1 Mathematical Derivation

For partition \((i,j)\), from the block system:

\[ \mathbf{A}_{i,j} \mathbf{v}_{i,j}^{(\text{int})} + \mathbf{B}_{i,j} \mathbf{v}_{i,j}^{(\text{port})} = \mathbf{b}_{i,j}^{(\text{int})} \quad (1) \] \[ \mathbf{B}_{i,j}^T \mathbf{v}_{i,j}^{(\text{int})} + \mathbf{D}_{i,j} \mathbf{v}_{i,j}^{(\text{port})} = \mathbf{b}_{i,j}^{(\text{port})} \quad (2) \]

From equation (1), solve for internal voltages:

\[ \mathbf{v}_{i,j}^{(\text{int})} = \mathbf{A}_{i,j}^{-1} \left( \mathbf{b}_{i,j}^{(\text{int})} - \mathbf{B}_{i,j} \mathbf{v}_{i,j}^{(\text{port})} \right) \quad (3) \]

Substitute (3) into (2):

\[ \mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \left( \mathbf{b}_{i,j}^{(\text{int})} - \mathbf{B}_{i,j} \mathbf{v}_{i,j}^{(\text{port})} \right) + \mathbf{D}_{i,j} \mathbf{v}_{i,j}^{(\text{port})} = \mathbf{b}_{i,j}^{(\text{port})} \]

Rearranging:

\[ \underbrace{\left( \mathbf{D}_{i,j} - \mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \mathbf{B}_{i,j} \right)}_{\mathbf{S}_{i,j}^{(\text{part})}} \mathbf{v}_{i,j}^{(\text{port})} = \underbrace{\mathbf{b}_{i,j}^{(\text{port})} - \mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \mathbf{b}_{i,j}^{(\text{int})}}_{\tilde{\mathbf{b}}_{i,j}^{(\text{port})}} \quad (4) \]
Definition: The Partition Schur Complement is: \[ \mathbf{S}_{i,j}^{(\text{part})} = \mathbf{D}_{i,j} - \mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \mathbf{B}_{i,j} \]

Step 2: Compute Schur (schur_complement in mtxOpts.cc:105-270):

void schur_complement(spMatrix *schur, // sparse D/S (intm-level) dsMatrix *dschur, // dense D/S (partition-level) spMatrix *mtx1, // A (already factored) spMatrix *mtx2, // B (coupling matrix) double threshold, cholmod_common *common, int intm_id, int id) { cholmod_factor *lu = mtx1->get_lu_mtx(); cholmod_sparse *m2 = mtx2->get_cholmod_mtx(); // Step 2a: C = L^{-1} * P * B (permuted forward solve) #ifdef PERC_CHOLMOD b = cholmod_spsolve(CHOLMOD_P, lu, m2, common); // apply permutation c = cholmod_spsolve(CHOLMOD_L, lu, b, common); // then forward solve #else c = cholmod_spsolve(CHOLMOD_LP, lu, m2, common); // fused P then L #endif // Step 2b: S = D - C^T * W * C, accumulated into schur and/or dschur. // Two variants, selected by Opts::MTX_SUPERNODAL_FACTOR: // true (LL^T ): W = I -> svmult(..., val) // false (LDL^T): W = D_L^{-1} -> svmult(..., d, val) <-- DEFAULT // Only the lower triangle is formed (j starts at i+1 for off-diagonals). for (i = 0; i < c->ncol; i++) // diagonals first if (svmult(col_i, col_i, ..., val)) { if (schur) schur->add_triplex_entry(i, i, -val); if (dschur) dschur->add_entry(i, i, -val); } for (i = 0; i < c->ncol; i++) { if (schur) di = schur->get_diag(i)*threshold; for (j = i+1; j < c->ncol; j++) { // off-diagonals, lower triangle if (schur) dj = schur->get_diag(j)*threshold; if (svmult(col_i, col_j, ..., val)) { if (schur) { // SPARSE path: sparsify here if (di > 0 && dj > 0 && fabs(val) < fabs(di) && fabs(val) < fabs(dj)) { schur->add_triplex_entry(i, i, -val); // lump onto schur->add_triplex_entry(j, j, -val); // the diagonal } else schur->add_triplex_entry(j, i, -val); } if (dschur) dschur->add_entry(j, i, -val); // DENSE: never dropped } } } }
Mathematical Correctness Verification:
  • \(\mathbf{A}_{i,j} = \mathbf{L}\mathbf{D}_L\mathbf{L}^T\) by default (MTX_SUPERNODAL_FACTOR = false, main.cc:291), or \(\mathbf{L}\mathbf{L}^T\) when it is true
  • \(\mathbf{C} = \mathbf{L}^{-1}\mathbf{B}_{i,j}\) (forward substitution, permutation applied)
  • \(\mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \mathbf{B}_{i,j} = \mathbf{B}_{i,j}^T \mathbf{L}^{-T}\mathbf{D}_L^{-1}\mathbf{L}^{-1}\mathbf{B}_{i,j} = \mathbf{C}^T \mathbf{D}_L^{-1} \mathbf{C}\) — the \(\mathbf{D}_L^{-1}\) weighting is the d[] array passed to svmult. In the \(\mathbf{L}\mathbf{L}^T\) case \(\mathbf{D}_L = \mathbf{I}\) and this reduces to \(\mathbf{C}^T\mathbf{C}\).

The port block initially contains \(\mathbf{D}_{i,j}\), and \(\mathbf{C}^T\mathbf{D}_L^{-1}\mathbf{C}\) is subtracted, giving \(\mathbf{S}_{i,j}^{(\text{part})}\). ✓

Note: sparsification (the diagonal-lumping branch) applies only to the sparse schur output. The dense dschur — which is what the partition level uses by default — receives every entry unconditionally. Lumping onto the diagonal rather than discarding preserves row sums, so the lumped matrix still annihilates the constant vector (see Section 15).

Phase 2: Assemble Intm Matrix

4. Assemble Intm Matrix

4.1 Mathematical Formulation

For intm \(i\) with partitions \(j \in \{0,1\}\), the tearing nodes are shared. Let:

  • \(\mathbf{u}_i\) = all tearing node voltages in intm \(i\)
  • \(\mathbf{P}_{i,j}\) = permutation/mapping matrix from local partition ports to global intm tearing nodes

The intm system is assembled as:

\[ \mathbf{M}_i^{(\text{intm})} = \sum_{j=0}^{1} \mathbf{P}_{i,j} \mathbf{S}_{i,j}^{(\text{part})} \mathbf{P}_{i,j}^T \]

This is the sum of partition Schur complements mapped to the common tearing node indices.

Phase 3: Intm Schur Complement

5. Intm Schur Complement

5.1 Mathematical Formulation

Now intm \(i\) has its own internal/port structure:

\[ \begin{bmatrix} \mathbf{A}_i^{(\text{intm})} & \mathbf{B}_i^{(\text{intm})} \\ \left(\mathbf{B}_i^{(\text{intm})}\right)^T & \mathbf{D}_i^{(\text{intm})} \end{bmatrix} \begin{bmatrix} \mathbf{u}_i^{(\text{int})} \\ \mathbf{u}_i^{(\text{port})} \end{bmatrix} = \begin{bmatrix} \tilde{\mathbf{b}}_i^{(\text{int})} \\ \tilde{\mathbf{b}}_i^{(\text{port})} \end{bmatrix} \]

Where:

  • \(\mathbf{u}_i^{(\text{int})}\) = tearing nodes internal to intm \(i\)
  • \(\mathbf{u}_i^{(\text{port})}\) = tearing nodes connected to intm2

The Intm Schur complement:

\[ \mathbf{S}_i^{(\text{intm})} = \mathbf{D}_i^{(\text{intm})} - \left(\mathbf{B}_i^{(\text{intm})}\right)^T \left(\mathbf{A}_i^{(\text{intm})}\right)^{-1} \mathbf{B}_i^{(\text{intm})} \quad (5) \]

Phase 5: RHS Compression

7. RHS Compression

7.1 Mathematical Formulation

At each level, the RHS must be transformed consistently with the Schur complement.

Partition level (from equation 4):

\[ \tilde{\mathbf{b}}_{i,j}^{(\text{port})} = \mathbf{b}_{i,j}^{(\text{port})} - \mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \mathbf{b}_{i,j}^{(\text{int})} \quad (6) \]

Intm level:

\[ \tilde{\mathbf{b}}_i^{(\text{port})} = \mathbf{b}_i^{(\text{port})} - \left(\mathbf{B}_i^{(\text{intm})}\right)^T \left(\mathbf{A}_i^{(\text{intm})}\right)^{-1} \mathbf{b}_i^{(\text{int})} \quad (7) \]

Where \(\mathbf{b}_i^{(\text{int})}\) is assembled from \(\tilde{\mathbf{b}}_{i,j}^{(\text{port})}\) of partitions.

7.2 Implementation

Partition RHS compression (mtxPart::compress_rhs, mtxPart.cc:778-792):

Phase 7: Back-Propagation

9. Back-Propagation

9.1 Mathematical Formulation

Now we have \(\mathbf{w}\) (intm2 tearing node voltages). We recover all unknowns by reversing the Schur complement elimination.

Level 1: Intm internal nodes

\[ \mathbf{u}_i^{(\text{int})} = \left(\mathbf{A}_i^{(\text{intm})}\right)^{-1} \left( \tilde{\mathbf{b}}_i^{(\text{int})} - \mathbf{B}_i^{(\text{intm})} \mathbf{u}_i^{(\text{port})} \right) \quad (9) \]

Where \(\mathbf{u}_i^{(\text{port})}\) is extracted from \(\mathbf{w}\) via port_map[i].

Level 2: Partition internal nodes

From equation (3):

\[ \mathbf{v}_{i,j}^{(\text{int})} = \mathbf{A}_{i,j}^{-1} \left( \mathbf{b}_{i,j}^{(\text{int})} - \mathbf{B}_{i,j} \mathbf{v}_{i,j}^{(\text{port})} \right) \quad (10) \]

Where \(\mathbf{v}_{i,j}^{(\text{port})}\) comes from intm \(i\)'s tearing nodes.

Mathematical Proof

10. Complete Mathematical Proof

Theorem: The hierarchical solve produces the exact solution.

Proof:

Let the original global system be \(\mathbf{M}\mathbf{v} = \mathbf{b}\).

Step 1: For each partition, the Schur complement \(\mathbf{S}_{i,j}^{(\text{part})} = \mathbf{D}_{i,j} - \mathbf{B}_{i,j}^T \mathbf{A}_{i,j}^{-1} \mathbf{B}_{i,j}\) eliminates the internal unknowns \(\mathbf{v}_{i,j}^{(\text{int})}\), creating an equivalent system on the port nodes.

Step 2: Assembling partition Schurs: \[ \mathbf{M}_i^{(\text{intm})} = \sum_j \mathbf{P}_{i,j} \mathbf{S}_{i,j}^{(\text{part})} \mathbf{P}_{i,j}^T \] This is mathematically equivalent to eliminating all partition-internal nodes from the global system, leaving only the intm tearing nodes.

Step 3: The intm Schur complement \(\mathbf{S}_i^{(\text{intm})}\) further eliminates intm-internal tearing nodes.

Step 4: The intm2 system \(\mathbf{M}^{(\text{intm2})} \mathbf{w} = \tilde{\mathbf{b}}^{(\text{intm2})}\) is the final reduced system containing only the top-level tearing nodes.

Step 5: Solving this gives the exact voltages at intm2 tearing nodes.

Step 6: Back-substitution at each level:

  • Equation (9) recovers intm-internal tearing nodes exactly
  • Equation (10) recovers partition-internal nodes exactly

Since each step is an exact algebraic transformation (no approximation except optional sparsification), the final solution \(\mathbf{v}\) satisfies the original system \(\mathbf{M}\mathbf{v} = \mathbf{b}\) exactly. ∎

11.2 Generic Matrix Structure at Each Level

This section describes the generic form of matrices at each level of the hierarchy.

Level 1: Partition Matrices

Each partition \(p\) has \(n_{\text{int}}\) internal nodes and \(n_{\text{port}}\) port connections to tearing nodes. The local system is:

\[ \begin{bmatrix} \mathbf{A}_p & \mathbf{B}_p \\ \mathbf{B}_p^T & \mathbf{D}_p \end{bmatrix} \begin{bmatrix} \mathbf{v}_p^{(\text{int})} \\ \mathbf{v}_p^{(\text{port})} \end{bmatrix} = \begin{bmatrix} \mathbf{b}_p^{(\text{int})} \\ \mathbf{b}_p^{(\text{port})} \end{bmatrix} \]
Matrix Definitions:
  • \(\mathbf{A}_p \in \mathbb{R}^{n_{\text{int}} \times n_{\text{int}}}\) — Internal-internal conductance matrix (stamped from edges between internal nodes)
  • \(\mathbf{B}_p \in \mathbb{R}^{n_{\text{int}} \times n_{\text{port}}}\) — Internal-port coupling matrix (stamped from edges between internal and port nodes)
  • \(\mathbf{D}_p \in \mathbb{R}^{n_{\text{port}} \times n_{\text{port}}}\) — Port-port conductance matrix (stamped from edges between port nodes, plus diagonal contributions from internal-port edges)

The Partition Schur Complement eliminates internal nodes:

\[ \mathbf{S}_p = \mathbf{D}_p - \mathbf{B}_p^T \mathbf{A}_p^{-1} \mathbf{B}_p \quad \in \mathbb{R}^{n_{\text{port}} \times n_{\text{port}}} \]

Level 2: Intm Matrices

Each intm \(i\) assembles partition Schur complements at shared tearing nodes. Let intm \(i\) have \(n_{\text{tnode}}\) tearing nodes, of which \(n_{\text{port}}\) are GPORTs (connected to intm2).

Assembly: The intm matrix is built by summing partition Schurs using port mappings:

\[ \mathbf{M}_i^{(\text{intm})} = \sum_{p \in \text{partitions of intm } i} \mathbf{P}_p \mathbf{S}_p \mathbf{P}_p^T \quad \in \mathbb{R}^{n_{\text{tnode}} \times n_{\text{tnode}}} \] where \(\mathbf{P}_p\) is the port mapping matrix from partition \(p\)'s local port indices to intm \(i\)'s tearing node indices.

Block Structure: After reordering to separate internal tearing nodes (LPORTs) from port tearing nodes (GPORTs):

Two different orderings — do not confuse them. simIntm keeps its tearing nodes in the tnodes[] array with GPORTs first: indices 0 .. nport-1 are GPORTs and nport .. ntnode-1 are LPORTs (SubGraph::pre_extract comments this as "global_port, local_port, internal nodes"). But simIntm::assign_int_unknown (simIntm.cc:203-214) assigns matrix unknown indices in the opposite order — LPORTs are numbered first (giving nunknown_int), GPORTs last (giving nunknown_port):
for (i = nport; i < ntnode; i++) // LPORTs -> unknowns 0 .. nunknown_int-1 tnodes[i].assign_unknown(nunknown); nunknown_int = nunknown; for (i = 0; i < nport; i++) // GPORTs -> the trailing unknowns tnodes[i].assign_unknown(nunknown); nunknown_port = nunknown - nunknown_int;
So in the matrix index space internal nodes come first and ports last, matching the mtxPart convention (index < nnode - nport ⇒ internal), and the \(\begin{bmatrix}\mathbf{A}&\mathbf{B}\\\mathbf{B}^T&\mathbf{D}\end{bmatrix}\) block form above is correct. The worked example below lists tearing nodes in array order (e.g. [n5, n9, n4] for Intm 0) and then states the internal/port split explicitly.
\[ \mathbf{M}_i^{(\text{intm})} = \begin{bmatrix} \mathbf{A}_i^{(\text{intm})} & \mathbf{B}_i^{(\text{intm})} \\ \mathbf{B}_i^{(\text{intm})T} & \mathbf{D}_i^{(\text{intm})} \end{bmatrix} \]
Matrix Definitions:
  • \(\mathbf{A}_i^{(\text{intm})} \in \mathbb{R}^{(n_{\text{tnode}} - n_{\text{port}}) \times (n_{\text{tnode}} - n_{\text{port}})}\) — Internal tearing nodes (LPORTs only)
  • \(\mathbf{B}_i^{(\text{intm})} \in \mathbb{R}^{(n_{\text{tnode}} - n_{\text{port}}) \times n_{\text{port}}}\) — Coupling between internal and port tearing nodes
  • \(\mathbf{D}_i^{(\text{intm})} \in \mathbb{R}^{n_{\text{port}} \times n_{\text{port}}}\) — Port tearing nodes (GPORTs)

The Intm Schur Complement eliminates internal tearing nodes:

\[ \mathbf{S}_i^{(\text{intm})} = \mathbf{D}_i^{(\text{intm})} - \mathbf{B}_i^{(\text{intm})T} \left(\mathbf{A}_i^{(\text{intm})}\right)^{-1} \mathbf{B}_i^{(\text{intm})} \quad \in \mathbb{R}^{n_{\text{port}} \times n_{\text{port}}} \]

\[ \mathbf{M}^{(\text{intm2})} = \begin{bmatrix} \frac{7}{5} & -\frac{7}{5} \\ -\frac{7}{5} & \frac{7}{5} \end{bmatrix} + \begin{bmatrix} \frac{7}{19} & -\frac{7}{19} \\ -\frac{7}{19} & \frac{7}{19} \end{bmatrix} = \begin{bmatrix} \frac{7}{5} + \frac{7}{19} & -\frac{7}{5} - \frac{7}{19} \\ -\frac{7}{5} - \frac{7}{19} & \frac{7}{5} + \frac{7}{19} \end{bmatrix} \] \[ \mathbf{M}^{(\text{intm2})} = \begin{bmatrix} \frac{168}{95} & -\frac{168}{95} \\ -\frac{168}{95} & \frac{168}{95} \end{bmatrix} \] Tearing node ordering: [n5, n9]
Verification: Every row of \(\mathbf{M}^{(\text{intm2})}\) sums to zero, and so does every row of each \(\mathbf{S}_p\), \(\mathbf{M}_i^{(\text{intm})}\) and \(\mathbf{S}_i^{(\text{intm})}\) above. This is the expected result and a useful self-check: the grid is a pure resistor network with no connection to ground, so its conductance matrix is a graph Laplacian and annihilates the constant vector \(\mathbf{1}\). Schur complementation preserves that property — if \(\mathbf{M}\mathbf{1} = \mathbf{0}\) then \(\mathbf{S}\mathbf{1} = \mathbf{0}\) — so the reduced matrix at every level must also have zero row sums, and \(\mathbf{M}^{(\text{intm2})}\) is singular. In a real IR-drop solve the system is made non-singular by voltage sources (grounded nodes), which is what breaks the zero-row-sum structure; this example has none.
End-to-end check: Eliminating all 14 non-port nodes directly from the full 16×16 grid Laplacian gives \(\begin{bmatrix} 168/95 & -168/95 \\ -168/95 & 168/95 \end{bmatrix}\) — identical to the hierarchically assembled \(\mathbf{M}^{(\text{intm2})}\) above. This confirms Theorem (Section 10) numerically on this example: the two-level Schur reduction reproduces the monolithic reduction exactly.

11.3 RHS Compression at Each Level

During the forward solve phase, the RHS vector is compressed at each level using the Schur complement. This section shows the RHS compression formulas and their application to the 4×4 grid example.

Level 1: Partition RHS Compression

For each partition \(p\), the original RHS is split into internal and port components. The compressed port RHS eliminates the internal contribution:

\[ \tilde{\mathbf{b}}_p^{(\text{port})} = \mathbf{b}_p^{(\text{port})} - \mathbf{B}_p^T \mathbf{A}_p^{-1} \mathbf{b}_p^{(\text{int})} \]
4×4 Grid Example: Partition RHS Compression

Assuming current sources inject current \(I\) at node n0 and extract at node n15 (i.e., \(b_0 = I\), \(b_{15} = -I\), all others zero):

Part 0 — Internal RHS: \(\mathbf{b}_0^{(\text{int})} = [I, 0]^T\), Port RHS: \(\mathbf{b}_0^{(\text{port})} = [0, 0]^T\)

\[ \mathbf{A}_0^{-1} = \frac{1}{3}\begin{bmatrix} 2 & 1 \\ 1 & 2 \end{bmatrix}, \quad \mathbf{A}_0^{-1} \mathbf{b}_0^{(\text{int})} = \frac{1}{3}\begin{bmatrix} 2I \\ I \end{bmatrix} \] \[ \mathbf{B}_0^T \mathbf{A}_0^{-1} \mathbf{b}_0^{(\text{int})} = \begin{bmatrix} 0 & -1 \\ -1 & 0 \end{bmatrix} \frac{1}{3}\begin{bmatrix} 2I \\ I \end{bmatrix} = \begin{bmatrix} -I/3 \\ -2I/3 \end{bmatrix} \] \[ \tilde{\mathbf{b}}_0^{(\text{port})} = \begin{bmatrix} 0 \\ 0 \end{bmatrix} - \begin{bmatrix} -I/3 \\ -2I/3 \end{bmatrix} = \begin{bmatrix} I/3 \\ 2I/3 \end{bmatrix} \] Port ordering: [n5, n4]

The intm RHS is assembled from partition compressed RHS vectors using the port mapping matrices:

\[ \mathbf{b}_i^{(\text{intm})} = \sum_{p \in \text{intm } i} \mathbf{P}_p \tilde{\mathbf{b}}_p^{(\text{port})} \]

\[ \tilde{\mathbf{b}}_i^{(\text{port})} = \mathbf{b}_i^{(\text{port})} - \mathbf{B}_i^{(\text{intm})T} \left(\mathbf{A}_i^{(\text{intm})}\right)^{-1} \tilde{\mathbf{b}}_i^{(\text{int})} \]

The intm2 RHS is assembled from intm compressed port RHS vectors using the Q mapping matrices:

\[ \tilde{\mathbf{b}}^{(\text{intm2})} = \sum_{i=0}^{1} \mathbf{Q}_i \tilde{\mathbf{b}}_i^{(\text{port})} \]
4×4 Grid Example: Intm2 RHS Assembly
\[ \tilde{\mathbf{b}}^{(\text{intm2})} = \mathbf{Q}_0 \tilde{\mathbf{b}}_0^{(\text{port})} + \mathbf{Q}_1 \tilde{\mathbf{b}}_1^{(\text{port})} \] Since \(\mathbf{Q}_0 = \mathbf{Q}_1 = \mathbf{I}_2\): \[ \tilde{\mathbf{b}}^{(\text{intm2})} = \tilde{\mathbf{b}}_0^{(\text{port})} + \tilde{\mathbf{b}}_1^{(\text{port})} = \begin{bmatrix} \tfrac{4I}{5} \\ \tfrac{I}{5} \end{bmatrix} + \begin{bmatrix} -\tfrac{8I}{19} \\ -\tfrac{11I}{19} \end{bmatrix} = \begin{bmatrix} \tfrac{36I}{95} \\ -\tfrac{36I}{95} \end{bmatrix} \] Tearing node ordering: [n5, n9]
End-to-end check: Compressing the RHS directly on the full 16×16 system — eliminating all 14 non-port nodes in one step — also yields \(\left[\tfrac{36I}{95},\, -\tfrac{36I}{95}\right]^T\), matching the hierarchically assembled result. Note the two entries sum to zero, as they must: the reduced RHS is a current balance, and the only sources are \(+I\) at n0 and \(-I\) at n15.
On solving this example: as noted in Section 11.2, \(\mathbf{M}^{(\text{intm2})}\) is singular here (zero row sums, no grounded node), so \(\mathbf{M}^{(\text{intm2})}\mathbf{w} = \tilde{\mathbf{b}}^{(\text{intm2})}\) determines \(v_5 - v_9 = \tfrac{36}{95}\cdot\tfrac{95}{168}I = \tfrac{3}{14}I\) but not the absolute voltages. This is the expected behaviour of a floating network, not a defect of the method; adding a single voltage source removes the null space.
Physical Interpretation: The RHS compression propagates external current injections up through the hierarchy. Current injected at internal nodes creates an "equivalent current" at port nodes through the Schur complement transformation. This ensures current conservation: the total current entering the circuit equals the total current leaving.

Direct Solve vs Iterative Solve

15. Direct Solve vs Iterative (CG) Solve

This section explains why the iterative Conjugate Gradient (CG) solver is used instead of relying solely on the hierarchical direct solve.

15.1 Key Finding: Direct Solve is NOT Exact Due to Sparsification

The hierarchical Schur complement solver uses sparsification to reduce memory usage and improve performance. Small entries are dropped from Schur complements:

// utils/options/option_globals.h:54-55 - namespace OptionDefaultValues (defaults only) constexpr double LEVEL1_SCHUR_TOL = 1.0e-4; constexpr double LEVEL2_SCHUR_TOL = 1.0e-4; // simulator/admin/global.h:298-300 - the actual mutable options namespace Opts { extern double LEVEL1_SCHUR_TOL; // LEVEL1/LEVEL2 are for the preconditioner extern double LEVEL2_SCHUR_TOL; extern double PART_SCHUR_TOL; // stores an accurate but sparsified per-part schur } // simulator/admin/main.cc:259-261 - definitions and defaults double LEVEL1_SCHUR_TOL = OptionDefaultValues::LEVEL1_SCHUR_TOL; // 1e-4 double LEVEL2_SCHUR_TOL = OptionDefaultValues::LEVEL2_SCHUR_TOL; // 1e-4 double PART_SCHUR_TOL = 1.0e-5;
Important: The constexpr values in option_globals.h are defaults living in namespace OptionDefaultValues. The variables actually read at runtime are the mutable doubles in namespace Opts (defined in admin/main.cc), which is why code elsewhere can assign Opts::LEVEL1_SCHUR_TOL = 0 (Section 15.6).
What sparsification actually does: a small off-diagonal entry is not simply discarded — it is lumped onto the two diagonal entries of its row and column (mtxOpts.cc, mtxPart::fill_intm_mtx). This preserves row sums, so the sparsified matrix remains a valid conductance matrix, but it is no longer the exact Schur complement.

Key Distinction — corrected:

mult_schur multiplies by the stored partition Schur matrix. It does not recompute \(\mathbf{B}^T\mathbf{A}^{-1}\mathbf{B}\mathbf{p}\) through the factorization on each CG iteration; there is no triangular solve in this path. The distinction that makes CG worthwhile is therefore about which stored matrix is used, and how accurate it is:

  • CG operator — the partition-level Schur. By default Opts::EXACT_PART_MTX is true (main.cc:219), so at the bottom level this is the dense dsMatrix schur, which schur_complement fills unconditionally — no entry is ever dropped or lumped. Hence the CG operator is the exact partition Schur complement (to round-off), which is what lets CG converge to the true solution. It is exact because it is dense and un-sparsified, not because it is recomputed.
  • Preconditioner — precond_solve() runs the hierarchical direct solve over the intm and intm2 matrices, which are sparsified (LEVEL1_SCHUR_TOL, LEVEL2_SCHUR_TOL). It is therefore approximate.

So the accuracy split is dense-partition-Schur (exact) as the operator vs. sparsified-upper-levels (approximate) as the preconditioner. If EXACT_PART_MTX were false, the partition level would use the sparse intm path and the CG operator would itself become approximate.

15.7 Summary: Why CG is Necessary

CG is necessary for exact solution because:
  1. The upper-level Schur matrices are sparsified — the intm and intm2 matrices have small off-diagonal entries lumped onto the diagonal (default 1e-4 relative tolerance), so the hierarchical direct solve is approximate.
  2. Preconditioner vs Solver — the hierarchical direct solve acts as a preconditioner, not the final solver. It gives a good approximation that CG refines.
  3. Exact operator — the CG matrix-vector product uses the dense, un-sparsified partition Schur complement (default EXACT_PART_MTX = true). It multiplies by the stored dense matrix rather than recomputing \(\mathbf{B}^T\mathbf{A}^{-1}\mathbf{B}\mathbf{p}\), but because that stored matrix had nothing dropped, the operator is exact to round-off.
  4. Convergence guarantee — CG on SPD matrices converges to the exact solution (within floating-point precision), regardless of preconditioner quality — provided the operator is exact, which is the point of item 3.

The design trades memory/speed (sparsified upper-level Schur storage and fast preconditioner application) for iteration count (typically few CG iterations needed due to good preconditioning).

16.1 Ownership and End-to-End Flow

\[ rk \le i < (r+1)k. \]

rank 0: simIntm[0] ... simIntm[k-1] each contains NPART2 complete simParts rank 1: simIntm[k] ... simIntm[2k-1] each contains NPART2 complete simParts ... rank 0 only: simIntm2 tearing nodes M^(intm2), its factorization, and the top-level direct solve

1. 16.2 Parse Distribution Is Not Solver Distribution

parallel_parser_node_based() is the MPI parser entry point for tiled input. It reads the tile-grid dimensions from partition_info, then part_tile() treats each tile as a weighted graph vertex, using its node count as the approximate parsing load. Recursive METIS divides this tile graph into \(p\) parts while balancing that load and favoring groups of connected tiles. METIS part \(r\) is assigned to rank \(r\), which parses only those tiles. The parser then applies the collected stitch-node names before DGraph::stitch().

16.3 Building and Stitching the Distributed Graph

After tile parsing, DGraph::synchronize_muts() reconciles distributed mutual-inductor metadata. Boundary-node identity is handled separately by the stitching flow below.

Stitching node. A stitching node is an ordinary Node marked as a candidate for cross-rank name matching. It is not yet a tearing node or an external node. For tiled device lines, Parser::fix_node_name() removes the leading * boundary marker and causes Graph::add_elem() to mark the device's terminal nodes. The link means “these parse-time copies are the same electrical node”; it is not a resistor and contributes no matrix stamp.

16.4.1 Global mode: USE_TILE_PARTITIONING == false

  1. Build distributed global CSR. DOneGraph::build_csr(GPORT) first builds local CSR rows, exchanges remote endpoint IDs for cross-rank edges, creates vtxdist from the per-rank vertex counts, and rebases every adjacency entry into global ParMETIS numbering. The rows remain distributed; no rank gathers the whole graph.
  2. Partition the stitched graph. DOneGraph::metis() calls ParMETIS_V3_PartKway() with \(pk\) target parts. Cross-rank physical connections therefore affect the cut.
  3. Assign an owner to every raw part. adjust_partid() measures how many vertices of each raw ParMETIS part are currently on each rank. It prefers the rank with the largest share, subject to the requirement that every rank receive exactly \(k\) intm IDs. It then renumbers IDs so owner(i) = i / k.
  4. Mark ports and migrate fragments. mark_part() exchanges the partition IDs at cross-rank edges and marks the resulting GPORT nodes. pre_extract() computes global node and port offsets. extract_subgraph() moves each fragment to its intm owner, which rebuilds the complete subgraph.

16.4.2 Tile-constrained mode: USE_TILE_PARTITIONING == true

Tile-constrained mode still runs DGraph::stitch(); the solver must retain the real cross-rank circuit connections. The difference is only the graph presented to the first-level partitioner. OneGraph::build_csr() omits external edges from local METIS adjacency, and DOneGraph::build_csr(GPORT) returns before remote-ID exchange and vtxdist construction.

DOneGraph::metis() enters with the global member npart = p*k. In tile-constrained mode it temporarily divides that value by nproc, so the local OneGraph::metis() call receives nparts = k. After local METIS returns, it restores the global count and converts each local label to global_intm_id = local_METIS_label + rank*k. Thus rank \(r\) creates \(k\) first-level parts with IDs \([rk,(r+1)k)\), and all ranks together still create \(pk\) intms.

16.5 Building Local simParts and the Rank-0 Top Level

After first-level extraction, simIntm2::build_intm2() creates objects only for the current rank's intm range. Each owned intm's extracted SubGraph is then partitioned locally into NPART2 simParts, exactly as in the single-process second-level partitioning flow.

A global tearing node is the single simIntm2 representation of a physical GPORT node shared by multiple first-level intms. When a circuit edge crosses an intm boundary, extraction retains the selected GPORT in each intm that needs that interface. These local GPORT views all represent the same circuit-node voltage, so simIntm2 maps them to one top-level tearing node and one top-level unknown. 16.6 The Seven Solve Phases under MPI

Single-process phase Default MPI execution
1. Partition Schur complement Each rank stamps, factors, and reduces its owned simParts locally.
2. Assemble intm matrix Each owned intm assembles its child Schur complements locally and applies the existing level-1 sparsification.
3. Intm Schur complement Each rank factors and reduces its owned intms locally.
4. Assemble and factor intm2 Rank 0 adds its local intm contributions directly. Workers send compact sparse intm contributions; rank 0 remaps them through each port_map, assembles and sparsifies the complete \(\mathbf{M}^{(\mathrm{intm2})}\), then factors it.
5. RHS compression Every rank compresses RHS vectors through its simParts and intms. Workers send only compressed intm port vectors; rank 0 accumulates them through port_map.
6. Top-level solve solve_direct() returns immediately on workers. Rank 0 solves the factored top-level matrix and sends each worker only the solution entries required by its owned intms.
7. Back-propagation Each rank propagates the received intm port values through its owned intms and simParts to recover local internal unknowns.
Default matrix layout. Lower-level matrices are distributed by complete object ownership. The final sparse \(\mathbf{M}^{(\mathrm{intm2})}\) is not block-row distributed; it exists and is factorized only on rank 0.

16.7 Distributed CG

solve_cg_dist() keeps the interpretation from Section 15: the hierarchical direct solve is the preconditioner, and the partition Schur matrices provide the operator application.

  1. Each rank stores and updates \(\mathbf{x}\), \(\mathbf{p}\), \(\mathbf{r}\), and \(\mathbf{z}\) for its owned simParts and performs the local Schur matrix-vector products.
  2. simIntm2::precond_solve() performs local intm compression, gathers the compressed top-level RHS on rank 0, runs the rank-0 direct solve, scatters the needed port solution values, and back-propagates locally.
  3. Each rank computes local contributions to \(\mathbf{r}^{T}\mathbf{z}\) and \(\mathbf{p}^{T}\mathbf{A}\mathbf{p}\). Rank 0 sums and broadcasts those scalars so all ranks use the same \(\alpha\), \(\beta\), and convergence state.
  4. Final partition-internal recovery remains local to the owning rank.

Thus the default MPI solver distributes parsing, graph construction, intm/simPart ownership, RHS work, and CG vector work, while centralizing only the final intm2 direct matrix and solve on rank 0.
